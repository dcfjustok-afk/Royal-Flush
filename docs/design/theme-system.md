# 多主题与界面尺度规范

更新时间：2026-08-25

## 设计方向

三套主题共享同一套信息层级、牌桌拓扑和交互语义，只改变环境气质。主题选择保存在浏览器中，刷新后恢复，并同步 `color-scheme` 与 `theme-color`。

| 主题 | 视觉方向 | 主色关系 | 使用场景 |
| --- | --- | --- | --- |
| 黑曜牌室 | 深夜私人牌室、工业设备感 | 暖黑底、骨白字、朱红行动、薄荷语音 | 默认主题；低光环境 |
| 象牙俱乐部 | 白昼编辑感、克制的老牌俱乐部 | 象牙纸色、深绿字、朱砂行动 | 明亮环境与高可读需求 |
| 午夜霓虹 | 实时转播台、深海电子感 | 深海蓝、冰青语音、珊瑚行动 | 偏冷色的沉浸式牌桌 |

主题只通过语义令牌控制背景、表面、文字、边线、牌桌、危险和等待状态。牌型、输赢、在线状态等含义不能只依赖颜色，必须同时保留文字或图标。

## 全界面尺度审查

| 界面 | 原问题 | 修正后的约束 | 验证 |
| --- | --- | --- | --- |
| 大厅与导航 | 主题入口缺失；次要文字偏小 | 主题入口常驻；正文与标签约 12–14px；主要控件不低于 40px | 四视口 E2E、浏览器目视 |
| 账号与邀请 | 独立头部无法切换主题；部分说明约 10px | 独立头部增加主题入口；表单 46px；错误就近播报 | 单元测试、桌面视觉回归 |
| 创建房间 | 表单缺少稳定字段名；标签偏小 | 字段名、自动填充策略、可点击标签和 44px 分段控件 | 类型检查、玩家流程 E2E |
| 等候室 | 辅助文字和快捷操作偏小 | 状态文字不低于约 12px；语音、准备、离开保持清晰层级 | 玩家流程 E2E、浏览器目视 |
| 沉浸式牌桌 | 高密度信息最低约 8–10px；主题入口易挤占横向空间 | 桌面信息约 12–13px；窄屏最低约 11px；主题入口折叠成 36–42px 图标选择器 | 四视口牌桌 E2E、视觉基线 |
| 个人资料与账本 | 账本需横向容纳固定列 | 表格自身横向滚动，不推动整页；数值使用等宽数字 | 玩家流程 E2E |
| 运营台 | 固定最小宽 1120px；大量 9–11px 文本 | 取消整页最小宽；低于 1000px 改为顶栏导航；低于 700px 单列；表格局部滚动 | 四视口主题 E2E、浏览器目视 |
| 抽屉与弹窗 | 小屏可能超宽；关闭按钮约 32–34px | 宽度受视口约束；内部滚动；关闭按钮 40px；危险操作保留确认 | 运营流程 E2E |

## 交互与可访问性底线

- 提供跳转到主要内容的键盘链接，所有图标按钮有可访问名称。
- 表单控件保留可点击标签、稳定 `name`、合理的 `autocomplete` 和输入类型。
- 所有焦点状态清晰可见；复合搜索框使用 `focus-within`。
- 状态、错误和异步结果使用 `role="status"`、`role="alert"` 或 `aria-live`。
- 尊重 `prefers-reduced-motion`，动画只改变 `transform` 或 `opacity`。
- 抽屉和弹窗使用 `overscroll-behavior: contain`；整页不得出现非预期横向滚动。

## 自动化门禁

`e2e/theme.spec.ts` 在桌面 1440、桌面 1280、手机竖屏和手机横屏中验证：

- 三套主题可切换；
- 主题刷新后保持；
- 浏览器主题色同步；
- 玩家端与运营端没有整页横向溢出；
- 当前页面所有可见按钮、输入框和选择器宽高均不小于 36px。
